# YouTube transcripts

- The tool's URL is constrained to http/https by the zod schema (`types.ts`) and re-checked with `validateUrl` at the top of `youtubeTranscript`, **before** either branch consumes it (no protocol or IP checks were ever applied to the yt-dlp branch previously).
- `yt-dlp` availability is probed with the pure-JS `which` package (a PATH walk using `node:fs`, no process or shell spawn) and cached with a TTL in the static `Fetcher.hasYtDlp`/`hasYtDlpAt` (default 60s, `Fetcher.checkTtlMs`) so a long-lived server picks up an install or removal. When available, subtitles are downloaded via `yt-dlp` into a `fetch-mcp-` dir under `os.tmpdir()` (`fs.mkdtempSync`, `.srv1` format, 30s timeout, cleaned up in `finally`), and the produced file is size-checked against `maxResponseBytes` before it is read. Any yt-dlp failure writes a one-line diagnostic to **stderr** and then falls back to direct page extraction.
- Direct extraction (`fetchTranscriptDirect`): locates `ytInitialPlayerResponse` in the watch page HTML with a balanced-brace scan (string-aware, so a `};` inside a JSON string value cannot truncate the object), picks the track matching `lang` else the **first** track (the requested language may not be what is returned), builds the caption URL with `new URL(track.baseUrl)` + `searchParams.set("fmt", "srv1")`, and fetches it through `_fetch` (so SSRF/size limits apply to it too).
- `lang` is regex-validated (`/^[a-zA-Z0-9][a-zA-Z0-9-]{0,9}$/`: alphanumeric first character, at most 10 characters, so a leading hyphen can never be re-parsed as a yt-dlp flag) in **two** places: inside `fetchTranscriptViaYtDlp` and again in `youtubeTranscript` before the try/catch. The second one is a security check that must not be swallowed by the fallback `catch` (keep both if you refactor).
- `parseTranscriptXml` handles two caption dialects: `<text ...>` (srv1, seconds) and `<p ...>` (srv3, milliseconds). Attribute matching is order-independent (`start`/`t` are extracted from the full attribute string, so `<p d=".." t="..">` still parses). `decodeHtmlEntities` covers the common named entities plus decimal and hex numeric references. If zero captions parse, the tool returns an error rather than a success with an empty transcript. Output is `[m:ss] content` lines prefixed with a `[Transcript language: ...]` header.
