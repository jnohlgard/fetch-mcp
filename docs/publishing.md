# Build and publishing

- `bun run build` uses `bun build --target node` with `--external jsdom --external @mozilla/readability --external turndown`. Those three stay as npm runtime dependencies (they're heavy); everything else is bundled. Output is ~1.3 MB for `index.js` (grew with the SDK v2 upgrade).
- npm package `@jnohlgard/fetch-mcp` exposes one bin: `fetch-mcp` (→ `dist/index.js`). `serve` starts the stdio MCP server; any other subcommand runs the CLI. `files` ships only `dist`, `README.md`, `LICENSE`. `prepublishOnly` re-runs the build.
- Version is bumped manually in `package.json` (no release automation).
- Publishing: bump the version, commit, and push to `main`. The `.github/workflows/draft-release.yml` workflow then makes sure the annotated `v{version}` tag exists (if you create it manually use `git tag -a`, not `git tag`; GitHub only lists annotated tags in the Releases UI and `git push tags` won't send a lightweight tag unless named explicitly) and creates a **draft** GitHub Release with auto-generated notes — it only skips when a release object for that tag already exists, so a tag without a release will still get one. A human reviews the draft on the GitHub UI and clicks **Publish**; that `release: published` event triggers `.github/workflows/publish.yml`, which verifies the tag matches the `package.json` version, runs `bun test`, and runs `npm publish --access public`. Publishing uses npm [trusted publishing](https://docs.npmjs.com/configuration/trusted-publishers) (OIDC from this repo/workflow — no `NPM_TOKEN` secret); the trusted publisher must be configured once on the npm package settings page with repo `jnohlgard/fetch-mcp`, workflow `.github/workflows/publish.yml`, and tag pattern `v*`.
- TypeScript is strict ESM (`"type": "module"`, `moduleResolution: "bundler"`); relative imports in `.ts` files use the `.js` extension (`import { Fetcher } from "./Fetcher.js"`).
